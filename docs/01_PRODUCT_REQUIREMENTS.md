# Docs Generator 要件定義書

## 1. 背景

今後はExcelではなくMarkdownを正式な設計書として取り扱う。

Excelを作成してからMarkdownへ変換する工程は廃止するが、Markdownを人間が一から作成すると、ファイル作成、見出し、表、共通情報、リンクの記述に時間がかかる。

Docs Generatorは、必要な設計書を選択し、必要項目を入力することで、一機能分のMarkdown設計書を直接生成するツールとする。

## 2. 目的

- 一機能分の設計書をMarkdownとして直接生成する。
- 定型的なファイル作成とMarkdown整形を自動化する。
- 共通情報を一度だけ入力し、複数設計書へ反映する。
- 必要な設計書だけを生成する。
- 提供されたテンプレートとほぼ同じ構造で出力する。
- 出力後のMarkdownを正式な設計書としてGit管理できるようにする。

## 3. 初期リリースの対象

1. 一機能分の共通情報入力
2. 生成する設計書の選択
3. 設計書固有項目の入力
4. Markdownソースのプレビュー
5. READMEと選択済み設計書の生成
6. ZIPダウンロード
7. 文字入力の自動保存
8. S-LayoutとR-Layoutへの画像添付

## 4. 初期リリースの対象外

実装規模を抑えるため、次は初期実装に含めない。

- Excelの読み込み、解析、変換
- 生成済みMarkdownの再読込
- 複数設計の一覧管理
- 複数下書き管理
- ユーザー登録、ログイン、権限管理
- サーバー側データベース
- 複数人同時編集
- GitHubへの直接コミット
- AIによる設計内容の生成、補完
- テンプレート編集画面
- WYSIWYGエディター
- 自由配置式レイアウトエディター
- 画像編集、トリミング、注釈描画
- フォルダへの直接保存
- SVG画像対応

## 5. 利用者

| 利用者 | 利用目的 |
| --- | --- |
| 設計担当者 | 必要項目を入力して設計書一式を作成する |
| 実装担当者 | Markdown設計書を参照して実装する |
| レビュー担当者 | Git差分と設計内容を確認する |
| AIエージェント | 定型構造の設計書を読み取る |

## 6. 基本利用フロー

1. ツールを開く。
2. システム名、機能ID、機能名などを入力する。
3. 基本6設計書を確認する。
4. 必要に応じて条件付き設計書を選択する。
5. 選択した設計書の内容を入力する。
6. Markdownプレビューを確認する。
7. ZIPを出力する。
8. 出力されたMarkdownを正式な設計書として管理する。

## 7. 共通入力項目

| 項目 | 必須 | 初期値・入力支援 |
| --- | --- | --- |
| システム名 | 必須 | 前回値を再利用可能 |
| モジュール名 | 任意 | 前回値を再利用可能 |
| モジュールID | 任意 | なし |
| 機能ID | 必須 | なし |
| 機能名 | 必須 | なし |
| 機能概要 | 必須 | なし |
| 文書番号 | 任意 | なし |
| 作成日 | 必須 | 当日 |
| Rev | 必須 | `0.1` |
| 作成者 | 必須 | 前回値を再利用可能 |
| 備考 | 任意 | なし |

## 8. 設計書選択

### 8.1 基本6設計書

初期状態で選択する。

- `Hist.md`
- `Outline_A.md`
- `Outline_B.md`
- `FuncSpec.md`
- `FuncDetail.md`
- `Relation.md`

### 8.2 条件付き6設計書

初期状態では選択しない。

- `S-Layout.md`
- `R-Layout.md`
- `Event.md`
- `Check.md`
- `Others.md`
- `Footnote.md`

利用者が必要なものだけを選択する。内容解析による自動提案は行わない。

## 9. 操作削減要件

- 共通情報は一度だけ入力する。
- 基本6設計書を初期選択する。
- 作成日とRevへ初期値を設定する。
- Histの初回行を共通情報から作成できる。
- 表の行を追加、削除、複製できる。
- 表の行を上下へ移動できる。
- No.を自動採番する。
- 未選択設計書の入力欄を表示しない。
- 文字入力をLocal Storageへ自動保存する。
- 全選択、基本のみ、全解除を用意する。

## 10. 出力要件

```text
<機能ID>_<機能名>/
├── README.md
└── sheets/
    └── 選択された設計書.md
```

- `README.md`だけをルートへ配置する。
- その他のMarkdownをすべて`sheets/`へ配置する。
- README索引には実際に生成したファイルだけを掲載する。
- 未選択の設計書を生成しない。
- 文字コードはUTF-8とする。
- 改行コードはLFとする。
- SQLを`sql`コードブロックで出力する。
- 入力内容を自動で補完、要約、変更しない。
- ZIPで一括ダウンロードできる。

## 11. 画像要件

- 初期対応はS-LayoutとR-Layoutだけとする。
- PNG、JPEG、WebPを添付できる。
- 画像を対象Markdownと同名のフォルダへ格納する。
- Markdownから相対パスで画像を表示する。
- 画像がない場合は画像フォルダを生成しない。
- 画像バイナリはLocal Storageへ保存しない。

## 12. 非機能要件

### 12.1 動作環境

- 最新版Chrome、Edge、Safari
- PC画面を主対象とする

### 12.2 セキュリティ

- 設計内容を外部サーバーへ送信しない。
- Markdownプレビューで入力文字列をHTMLとして実行しない。
- 画像ファイル名から相対パス遷移を除去する。

### 12.3 保守性

- テンプレートを出力形式の正本とする。
- 設計書ごとの生成処理を関数単位で分ける。
- 独自テンプレート言語を作成しない。
- 初期実装のために将来機能を先行実装しない。

## 13. 受け入れ条件

1. 一機能分の設計情報を入力できる。
2. 基本6設計書が初期選択される。
3. 条件付き6設計書を選択できる。
4. 共通情報が全設計書へ反映される。
5. 選択済み設計書だけが生成される。
6. 提供テンプレートとほぼ同じ見出し、表、順序で生成される。
7. README索引と実ファイルが一致する。
8. ZIPを出力できる。
9. 文字入力を再読み込み後に復元できる。
10. S-LayoutとR-Layoutの画像を同名フォルダへ出力できる。
11. バックエンドなしで動作する。
