# Docs Generator 画像対応実装計画

## 1. 目的

レイアウト設計書を中心に画像を添付し、対象Markdown名と同名のフォルダへ画像を出力できるようにする。

画像対応は、単なるファイル添付ではなく、入力、プレビュー、自動保存、検証、ZIP出力、再読込まで一貫した機能として実装する。

## 2. 対象範囲

初期リリースでは次を対象とする。

- `S-Layout.md`への画像添付
- `R-Layout.md`への画像添付
- PNG、JPEG、WebP、SVG
- ドラッグ&ドロップ
- ファイル選択
- クリップボード貼り付け
- サムネイル表示
- 代替テキストとキャプション
- 表示順変更
- IndexedDBへの自動保存
- Markdownプレビュー
- ZIP・フォルダ出力
- 生成済みパッケージからの再読込

内部モデルは全設計書で画像を扱える共通構造にする。

## 3. 実装順序

## IM01 画像ドメインモデル

### 作業

- `DocumentImageAsset`を実装する。
- 対応MIME typeを定義する。
- 画像サイズ、ファイル数、パッケージ容量の制限を定義する。
- 画像と設計書、セクション、画面領域、レイアウトブロックの関連を定義する。
- 画像ファイル名正規化処理を実装する。
- 同一フォルダ内の重複回避処理を実装する。

### 完了条件

- 画像メタデータを型安全に保持できる。
- 元ファイル名から安全な出力ファイル名を生成できる。
- 大文字小文字を無視した重複を解消できる。

## IM02 IndexedDB画像保存

### 作業

- 画像Blob用テーブルをDexieへ追加する。
- プロジェクトと画像メタデータの関連を保存する。
- 画像追加、置換、削除、復元を実装する。
- プロジェクト削除時に画像も削除する。
- 保存容量不足エラーを処理する。

### 完了条件

- ブラウザ更新後も画像を復元できる。
- 削除した設計に孤立画像が残らない。
- 画像保存失敗時に入力内容を失わない。

## IM03 画像入力コンポーネント

### 作業

- ドロップゾーンを実装する。
- ファイル選択を実装する。
- クリップボード貼り付けを実装する。
- 対応形式、サイズ、ファイル数を事前検証する。
- 複数ファイルの一括追加を実装する。
- SVGの安全性検証を実装する。

### 完了条件

- 対応画像を3方式で追加できる。
- 非対応ファイルが明確に拒否される。
- 追加順が初期表示順になる。

## IM04 画像一覧編集

### 作業

- サムネイル一覧を実装する。
- 代替テキスト、キャプション、ファイル名を編集できるようにする。
- 表示セクションと関連対象を選択できるようにする。
- 並び替え、置換、削除、Undoを実装する。
- 拡大プレビューを実装する。

### 完了条件

- 画像の表示順を変更できる。
- S-Layoutの画面領域、R-Layoutのレイアウトブロックへ関連付けできる。
- 削除を取り消せる。

## IM05 テンプレート対応

### 作業

- `S-Layout.md`へ`Screen images`セクションを追加する。
- `R-Layout.md`へ`Layout images`セクションを追加する。
- 画像配列をテンプレートコンテキストへ追加する。
- 画像、代替テキスト、キャプション、相対パスを展開する。
- 画像なし時の互換モードと簡潔モードを実装する。

### 完了条件

- 提供テンプレートの基本構造を維持しつつ画像を表示できる。
- 画像がない設計書で不要な画像フォルダを生成しない。
- Markdownへ絶対パスが出力されない。

## IM06 プレビュー対応

### 作業

- BlobからObject URLを作成する。
- Markdownプレビューの画像パスをObject URLへ解決する。
- 画像追加、置換、削除時にプレビューを更新する。
- 不要なObject URLを破棄する。
- 画像読込失敗表示を実装する。

### 完了条件

- 出力前にMarkdown内の表示状態を確認できる。
- 画像差し替えがプレビューへ即時反映される。
- Object URLのリークが発生しない。

## IM07 ExportService対応

### 作業

- 画像を`GeneratedFile`のバイナリ対応モデルへ追加する。
- `sheets/<DocumentName>/`を生成する。
- 画像バイナリをZIPへ追加する。
- File System Access APIで画像を書き込む。
- Markdown参照と出力画像を照合する。
- 未参照画像と参照切れを検出する。

### 完了条件

- `S-Layout.md`の画像が`sheets/S-Layout/`へ出力される。
- `R-Layout.md`の画像が`sheets/R-Layout/`へ出力される。
- ZIP展開後にMarkdownから画像を表示できる。
- 画像が0件の場合は同名フォルダを作成しない。

## IM08 ImportService対応

### 作業

- Markdown画像構文を解析する。
- 相対パスを安全に解決する。
- 画像ファイルをBlobへ復元する。
- 代替テキスト、キャプション、表示順を復元する。
- 未解決画像、未参照画像、規約外フォルダを検出する。
- 外部URL画像を警告する。

### 完了条件

- 本ツールで生成した画像付きパッケージを再読込できる。
- 再出力後も画像の表示順、代替テキスト、キャプションが保持される。
- 不正な相対パスを読み込まない。

## IM09 セキュリティ・性能

### 作業

- MIME type、拡張子、ファイルシグネチャを検証する。
- SVGをサニタイズする。
- Zip Slipを防止する。
- 展開後容量とファイル数を制限する。
- 大画像のサムネイル生成をWeb Workerで行うことを検討する。
- 大容量画像の警告を実装する。

### 完了条件

- SVG内のスクリプトと外部参照を除去または拒否できる。
- `../`を含む画像パスを拒否できる。
- 大量画像追加でUIが長時間停止しない。

## IM10 E2E・リリース確認

### E2Eシナリオ

1. 画面機能を新規作成する。
2. S-Layoutを選択する。
3. 画面画像を3件追加する。
4. 代替テキストとキャプションを入力する。
5. 画像を並び替える。
6. ZIPを出力する。
7. ZIPを展開し、Markdownから画像を表示できることを確認する。
8. ZIPを再読込する。
9. 画像を1件置換する。
10. 再出力し、変更が保持されることを確認する。

### 完了条件

- 全E2Eシナリオが成功する。
- 画像付きパッケージでもREADME索引と設計書一覧が一致する。
- 参照切れと孤立画像がない。

## 4. データ構造変更

`GeneratedFile`はテキストとバイナリを扱える形へ変更する。

```ts
type GeneratedFile = GeneratedTextFile | GeneratedBinaryFile;

interface GeneratedTextFile {
  kind: "text";
  path: string;
  content: string;
  documentType?: DocumentType;
}

interface GeneratedBinaryFile {
  kind: "binary";
  path: string;
  content: Blob;
  documentType: DocumentType;
  assetId: string;
}
```

## 6. 実装優先度

画像対応は、基本6設計書のMarkdown生成とZIP出力が完成した後、条件付き設計書の実装と同時に開始する。

優先順は次とする。

1. S-Layout画像追加・出力
2. R-Layout画像追加・出力
3. 自動保存とプレビュー
4. 再読込
5. 全設計書への共通画像対応

## 7. 禁止事項

- Base64画像をMarkdown本文へ埋め込まない。
- すべての画像を`sheets/images`へ集約しない。
- 対象Markdown名と異なる画像フォルダ名を生成しない。
- 外部URL画像を無断でダウンロードしない。
- 画像を失った状態で再出力を続行しない。
- SVGを未検証のままプレビューしない。
