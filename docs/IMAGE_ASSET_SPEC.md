# レイアウト画像添付仕様

## 1. 目的

`S-Layout.md`および`R-Layout.md`では、画面イメージ、ワイヤーフレーム、帳票見本、出力例などの画像を設計書へ添付できるようにする。

画像はMarkdownへ埋め込まず、設計書と同名のフォルダへファイルとして格納し、Markdownから相対パスで表示する。

## 2. 対象設計書

初期実装で画像添付を許可する設計書は次の2種類に限定する。

- `S-Layout.md`
- `R-Layout.md`

他の設計書への画像添付は初期実装の対象外とする。

## 3. 出力フォルダ構成

画像が添付された場合、`sheets`フォルダの直下に設計書と同名の画像格納フォルダを作成する。

```text
<FunctionId>_<FunctionName>/
├── README.md
└── sheets/
    ├── S-Layout.md
    ├── S-Layout/
    │   ├── screen-overview.png
    │   └── search-area.png
    ├── R-Layout.md
    └── R-Layout/
        └── report-sample.png
```

画像が1枚もない設計書については、同名フォルダを作成しない。

## 4. Markdownからの参照

Markdownファイルは`sheets`直下にあるため、画像は次の相対パスで参照する。

### S-Layout.md

```markdown
![画面全体](./S-Layout/screen-overview.png)
```

### R-Layout.md

```markdown
![帳票出力例](./R-Layout/report-sample.png)
```

絶対パス、ローカルPC上のパス、Base64データはMarkdownへ出力しない。

## 5. テンプレートへの追加

`S-Layout.md`と`R-Layout.md`の末尾に、次のブロックトークンを追加する。

```text
{{LAYOUT_IMAGE_SECTION}}
```

画像がある場合、レンダラーが次の形式のMarkdownを生成して差し込む。

```markdown
### 4.5 Layout images

#### 4.5.1 画面全体

![画面全体](./S-Layout/screen-overview.png)

- File: `S-Layout/screen-overview.png`
- Notes: 初期表示時の画面全体
```

画像がない場合、`{{LAYOUT_IMAGE_SECTION}}`は空文字へ置換し、`4.5 Layout images`自体を出力しない。

これにより、既存テンプレートの`4.1`から`4.4`までの構造を変更しない。

## 6. 入力項目

画像1件につき、次の情報を保持する。

| 項目 | 必須 | 内容 |
| --- | --- | --- |
| 画像ファイル | 必須 | 利用者が選択した画像 |
| 表示名 | 任意 | 画像セクションの見出し。未入力時はファイル名を使用 |
| 代替テキスト | 任意 | Markdown画像のalt。未入力時は表示名を使用 |
| 備考 | 任意 | 画像の説明 |
| 表示順 | 必須 | 追加順を初期値とし、上下移動可能 |

## 7. 画面操作

S-LayoutまたはR-Layoutを選択した場合だけ、画像添付欄を表示する。

初期実装で提供する操作は次のとおり。

- 画像選択
- 複数画像の一括選択
- 画像プレビュー
- 表示名、代替テキスト、備考の入力
- 上へ移動
- 下へ移動
- 削除

次の操作は実装しない。

- 画像編集
- トリミング
- リサイズ
- 回転
- 画像への注釈描画
- ドラッグ&ドロップによる並び替え

## 8. 対応ファイル形式

初期実装では次の形式のみ受け付ける。

- PNG: `.png`
- JPEG: `.jpg`, `.jpeg`
- WebP: `.webp`

SVG、GIF、PDF、Officeファイルは対象外とする。

## 9. ファイル名ルール

ZIPへ格納する前に、画像ファイル名を安全な形式へ変換する。

1. 拡張子は小文字へ統一する。
2. `/`、`\`、`:`, `*`, `?`, `"`, `<`, `>`, `|`を`_`へ置換する。
3. 先頭と末尾の空白を除去する。
4. `.`または空文字だけのファイル名は使用しない。
5. 同名ファイルがある場合は`-2`、`-3`を付与する。
6. `../`など、上位フォルダを参照できる文字列を許可しない。

例:

```text
画面/全体.PNG
    ↓
画面_全体.png
```

## 10. データモデル

```ts
interface LayoutImage {
  id: string;
  originalFileName: string;
  outputFileName: string;
  mimeType: "image/png" | "image/jpeg" | "image/webp";
  title: string;
  alt: string;
  notes: string;
  order: number;
  file: File;
}
```

S-LayoutとR-Layoutの入力モデルに、それぞれ`images: LayoutImage[]`を追加する。

## 11. 保存方針

画像バイナリはLocal Storageへ保存しない。

理由は次のとおり。

- Local Storageの容量制限を超えやすい。
- Base64化によりデータ量が増える。
- 画像永続化のためにIndexedDBを導入すると実装規模が増える。

初期実装では次の動作とする。

- 文字入力と画像メタデータは通常どおり自動保存する。
- 画像ファイル本体は画面を開いている間だけ保持する。
- 画像が選択された状態でページ離脱または再読み込みを行う場合は警告する。
- 再読み込み後は画像ファイルを再選択する。

将来、再選択の負担が問題になった場合だけIndexedDB対応を検討する。

## 12. プレビュー

選択直後の画像表示には`URL.createObjectURL`を使用する。

画像を削除したとき、別画像へ置き換えたとき、画面を破棄するときは`URL.revokeObjectURL`を実行する。

Markdownプレビューでは、ZIP内と同じ相対パス文字列を表示するとともに、画面上では選択中のFileオブジェクトから画像を表示する。

## 13. ZIP生成

ZIP生成時は次の順で処理する。

1. 画像ファイル名を正規化する。
2. 同名ファイルを解決する。
3. Markdownの画像参照ブロックを生成する。
4. `sheets/S-Layout.md`または`sheets/R-Layout.md`を追加する。
5. 画像を`sheets/S-Layout/`または`sheets/R-Layout/`へバイナリのまま追加する。
6. Markdown内の参照先とZIP内のパスが一致することを検証する。

## 14. バリデーション

- 対応外形式は追加できない。
- 画像1枚の上限は10MBとする。
- 1設計書あたり最大10枚とする。
- ファイル読み込みに失敗した画像は出力しない。
- Markdownで参照している画像がZIP内に存在しない場合、ZIP出力を停止する。
- ZIP内に未参照の画像が存在する場合、警告を表示する。

## 15. テスト項目

1. S-Layout画像が`sheets/S-Layout/`へ出力される。
2. R-Layout画像が`sheets/R-Layout/`へ出力される。
3. Markdownの相対パスで画像を表示できる。
4. 画像なしの場合に画像フォルダと画像セクションが生成されない。
5. 複数画像が指定順で出力される。
6. 同名画像に連番が付く。
7. 不正なファイル名が正規化される。
8. 対応外形式とサイズ超過を拒否できる。
9. Markdown参照先とZIP内画像の存在を検証できる。
10. 画像削除後にZIPへ残らない。

## 16. 受け入れ条件

1. S-LayoutとR-Layoutへ画像を添付できる。
2. 画像が設計書と同名のサブフォルダへ格納される。
3. Markdownから相対パスで画像を表示できる。
4. 複数画像の順序と説明を設定できる。
5. 画像なしの場合は既存テンプレート構造を維持できる。
6. バックエンドや画像編集ライブラリを追加せずに実装できる。
