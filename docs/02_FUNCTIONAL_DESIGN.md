# Docs Generator 機能設計書

## 1. 画面構成

初期実装は、次の5画面で構成する。

| 画面ID | 画面名 | 目的 |
| --- | --- | --- |
| DG01 | ホーム | 新規作成、再開、複製、インポートを開始する |
| DG02 | 基本情報・設計書選択 | 共通情報と生成対象を決定する |
| DG03 | 設計内容編集 | 選択した設計書の内容を入力する |
| DG04 | プレビュー・検証 | 生成結果と不備を確認する |
| DG05 | 出力 | ZIPまたはフォルダへ保存する |

画面遷移はウィザード形式を基本とするが、編集開始後は左ナビゲーションから任意の設計書へ直接移動できるようにする。

```text
│ 基本情報       │                                              │
│ Hist          │                編集領域                      │

```

  - インポート

### 2.2 左ナビゲーション

- 基本情報
- 選択済み設計書一覧
- 各設計書の入力状態

  - 警告あり

- 設計書追加ボタン

- セクション単位の入力フォーム

- 繰り返し行の追加・削除・複製・並び替え
- フィールド単位のエラー表示

## 3. DG01 ホーム

### 3.1 表示内容

- 「新しい機能設計を作成」ボタン
- 「Markdownパッケージを読み込む」ボタン
- 最近編集した設計一覧
- プロジェクトプリセット一覧

### 3.2 最近編集した設計一覧

| 項目 | 内容 |
| --- | --- |
| 機能ID | 設計対象機能のID |
| 機能名 | 設計対象機能名 |
| システム名 | 所属システム |
| 更新日時 | 最終自動保存日時 |
| 状態 | 編集中、検証済み、出力済み |
| 操作 | 開く、複製、削除、出力 |

### 3.3 新規作成時の省操作

「新しい機能設計を作成」を押した後、次を一つの開始ダイアログで入力する。

- 使用するプロジェクトプリセット
- 機能種別
- 機能ID
- 機能名

確定後、その他の共通項目はプリセットと初期値から自動設定し、DG02へ遷移する。

## 4. DG02 基本情報・設計書選択

### 4.1 基本情報

| 項目 | 必須 | 初期値・入力支援 |
| --- | --- | --- |
| システム名 | 必須 | プロジェクトプリセット |
| モジュール名 | 任意 | プロジェクトプリセットまたは前回値 |
| モジュールID | 任意 | プロジェクトプリセットまたは前回値 |
| 機能ID | 必須 | 開始ダイアログの入力値 |
| 機能名 | 必須 | 開始ダイアログの入力値 |
| 機能種別 | 必須 | 開始ダイアログの選択値 |
| 作成者 | 必須 | 前回値 |
| 作成日 | 必須 | 当日日付 |
| Rev | 必須 | `1.0` |
| 文書番号 | 任意 | プリセット規則による自動生成候補 |
| 概要 | 必須 | 手入力 |
| 出力言語 | 必須 | `日本語` |

### 4.2 設計書選択

#### 基本選択

次は選択済みで開始する。

- Hist
- Outline_A
- Outline_B
- FuncSpec
- FuncDetail
- Relation

#### 機能種別別の推奨

| 機能種別 | 追加推奨 |
| --- | --- |
| 画面 | S-Layout、Event、Check、Footnote |
| API | Check、Event、Footnote |
| バッチ | Event、Check、Others、Footnote |
| 帳票 | R-Layout、Check、Footnote |
| 共通機能 | Others、Check、Footnote |
| その他 | 明示的な自動追加なし |

推奨は初期選択候補であり、利用者が変更できる。

### 4.3 内容による追加提案

編集中に次の内容が入力された場合、未選択の関連設計書を追加提案する。

| 検出内容 | 提案 |
| --- | --- |
| 画面項目、ボタン、入力欄 | S-Layout |
| 帳票、CSV、PDF、出力列 | R-Layout |
| 入力チェック、業務チェック、メッセージID | Check |
| イベント、トリガー、定期実行 | Event |
| 定数、コード値、ファンクションキー | Others |
| 略語、注釈、用語定義 | Footnote |

提案は通知として表示し、自動追加はしない。

## 5. DG03 設計内容編集

## 5.1 共通動作

- 入力は500ms程度のデバウンス後に自動保存する。
- 入力変更と同時にMarkdown生成モデルを更新する。
- 入力済みの共通項目は全設計書へ自動反映する。
- セクション内の表は行追加、削除、複製、ドラッグ並び替えができる。
- 削除はUndo可能とする。
- 長文欄はMarkdown記法を許可する。
- SQL欄は等幅フォント、行番号、タブ入力に対応する。

## 5.2 Hist入力

### 自動生成項目

新規作成時に初回履歴行を生成する。

| 項目 | 初期値 |
| --- | --- |
| 作成・更新日 | 作成日 |
| 作成者 | 共通メタデータの作成者 |
| Rev. | 共通メタデータのRev |
| 対象 | 全体 |
| 変更内容 | 新規作成 |

利用者は履歴行を追加・修正できる。

## 5.3 Outline_A入力

- 目的
- 対象範囲
- 対象ユーザー・対象処理
- 前提条件
- 操作・処理フロー
- 後続条件
- 備考

処理フローはステップの繰り返し入力とし、並び替え可能とする。

## 5.4 Outline_B入力

- 処理方式・分類
- CRUD・操作区分
- 関連テーブル
- 関連マスタ
- 関連API・外部インターフェース
- 運用制約
- 備考

CRUDはCreate、Read、Update、Delete、Noneを選択式で入力できる。

## 5.5 FuncSpec入力

機能単位を複数追加できる。

各機能単位に次を持つ。

- 機能名
- トリガー・タイミング
- 目的
- 主要処理ステップ
- 正常終了時の動作
- エラー・中断時の動作
- 関連画面項目
- 関連詳細処理
- 備考

主要処理ステップは番号を自動採番する。

## 5.6 FuncDetail入力

処理単位を複数追加できる。

各処理単位に次を持つ。

- 処理番号
- 処理名
- 関数・メソッド名
- 関数種別
- 処理概要
- 前提条件
- 入力
- 出力
- 内部処理ステップ
- 検証処理
- DB処理
- トランザクション処理
- 例外処理
- finally処理
- 呼出共通処理
- 関連設計書
- 備考

空の`try / catch / finally`見出しは出力せず、入力がある部分だけを生成する。

## 5.7 Relation入力

リレーション定義を複数追加できる。

各定義に次を持つ。

- リレーション名
- 用途
- Transfer Source
  - 種別
  - エンティティ・テーブル名
  - 項目名
  - 条件
- Transfer Destination
  - 種別
  - エンティティ・テーブル名
  - 項目名
  - 条件
- マッピング表
- SQL
- 備考

Transfer SourceとTransfer Destinationは別セクションとして入力・出力する。

## 5.8 S-Layout入力

- 画面名
- 画面概要
- 画面領域
- コントロール一覧
- コントロール属性
- 表示ルール
- 編集可否ルール
- 初期値
- 備考

同一コントロールIDを複数表で選択できるよう、コントロール一覧を基準データとする。

## 5.9 R-Layout入力

- 出力名
- 出力形式
- レイアウトブロック
- 出力項目
- 列定義
- 改ページ・出力制御
- ファイル名規則
- 備考

## 5.10 Event入力

- イベント名
- トリガー
- 対象機能・処理
- 発生条件
- 実行内容
- 備考

## 5.11 Check入力

- チェック対象
- チェック名
- 実行タイミング
- チェック一覧
  - No.
  - チェック項目
  - 種別
  - 条件・詳細
  - エラー時動作
  - メッセージID
  - メッセージ引数

No.は自動採番し、必要な場合のみ手動変更可能とする。

## 5.12 Others入力

- 共通定数
- コード値
- 選択肢
- ファンクションキー割当
- 補助マッピング
- 運用補足

## 5.13 Footnote入力

- 用語
- 略称・コード
- 注釈
- 補足説明

## 6. DG04 プレビュー・検証

### 6.1 レイアウト

- 左側：生成ファイル一覧
- 中央：Markdownレンダリング
- 右側：エラー・警告一覧
- 切替：Markdownソース表示

### 6.2 検証結果

| レベル | 動作 |
| --- | --- |
| Error | 出力不可。該当入力欄へのリンクを表示する |
| Warning | 内容確認後に出力可能 |
| Info | 自動補正や推奨事項を表示する |

### 6.3 主なエラー

- 機能IDまたは機能名が未入力
- ファイル名を生成できない
- README索引対象と生成対象が一致しない
- 必須設計書の生成モデルが存在しない
- 参照先ファイルが未選択
- Markdown生成処理に失敗

### 6.4 主な警告

- 基本設計書が解除されている
- 選択した設計書の主要セクションがすべて空
- 関連情報があるが推奨設計書が未選択
- 空行だけの表データが存在する
- 手動編集されたMarkdownを完全復元できない

## 7. DG05 出力

### 7.1 出力方法

- ZIPダウンロード
- フォルダ選択による直接保存
- 各ファイルの個別ダウンロード
- Markdownソースのクリップボードコピー

### 7.2 出力前確認

- 出力フォルダ名
- 生成ファイル一覧
- エラー件数
- 警告件数
- 既存ファイル上書きの有無

### 7.3 完了表示

- 出力結果
- ファイル数
- 出力日時
- 出力先
- 続けて編集
- この機能を複製して新規作成

## 8. インポート仕様

### 8.1 入力方法

- ZIPファイル選択
- フォルダ選択
- READMEと`sheets`一式のドラッグ&ドロップ

### 8.2 読込手順

1. READMEを検出する。
2. Sheet indexから対象ファイルを列挙する。
3. 各Markdownを規定見出しで解析する。
4. 共通メタデータを統合する。
5. 各設計書の入力モデルへ復元する。
6. 構造差異を警告する。
7. 編集画面を表示する。

### 8.3 読込制約

- 規定見出しを変更したファイルは部分読込になる可能性がある。
- 未知のセクションは削除せず、未解析ブロックとして保持する方針とする。
- 再出力時に利用者の記述を失わないことを優先する。

## 9. 操作削減ルール

- 新規作成時は4項目だけで編集を開始できる。
- 共通情報は一箇所だけで編集する。
- 日付、Rev、初回履歴を自動設定する。
- 機能種別で設計書を推奨する。
- 表のNo.は自動採番する。
- 相互参照候補は選択済み設計書から自動生成する。
- 同じ機能名、画面名、処理名を候補として再利用する。
- 入力内容は自動保存する。
- 既存機能を複製できる。
- 未入力セクションは折りたたみ、必要時に展開する。
- Markdown記法を利用者に強制せず、フォーム入力から生成する。
