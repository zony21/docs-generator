# Docs Generator 実装計画

## 1. 実装方針

- 一機能分のMarkdown設計書を作成してZIP出力する最小構成を先に完成させる。
- 画面は1画面だけとする。
- Vite、TypeScript、HTML、CSS、JSZipだけを中心に実装する。
- 基本6設計書を先に完成させ、その後に条件付き6設計書を追加する。
- テンプレートは単純なトークン置換で展開する。
- 将来機能を理由に初期実装を複雑化しない。

## 2. 初期完成条件

1. 共通情報を入力できる。
2. 基本6設計書が初期選択される。
3. 条件付き6設計書を選択できる。
4. 選択済み設計書の内容を入力できる。
5. Markdownソースをプレビューできる。
6. READMEと選択済み設計書をZIP出力できる。
7. 文字入力をLocal Storageへ自動保存できる。
8. S-LayoutとR-Layoutへ画像を添付できる。
9. 画像を対象Markdownと同名のフォルダへ出力できる。
10. バックエンドなしで動作する。

## 3. 初期実装へ含めないもの

- Vue、React
- Router
- 状態管理ライブラリ
- IndexedDB、Dexie
- Handlebars
- Markdown再読込
- 複数プロジェクト管理
- 複数下書き
- ファイルシステムへの直接保存
- GitHub連携
- AI生成
- ドラッグ&ドロップ並び替え
- Undo
- 画像編集
- SVG対応
- E2Eフレームワーク

## 5. 実装ステップ

## Step 1. 開発基盤とテンプレート読込

### 作業

1. Vite + TypeScriptプロジェクトを作成する。
2. JSZipとVitestを追加する。
3. 13個のMarkdownテンプレートをraw importする。
4. `DocumentType`とテンプレート、出力パス、順序を静的に定義する。
5. テンプレートの存在と必須トークンを検証するテストを作成する。

### 完了条件

- `npm run dev`で起動できる。
- `npm run build`が成功する。
- 13個のテンプレートを読み込める。
- テンプレート不足をテストで検出できる。

## Step 2. 共通情報と設計書選択

### 作業

1. `DesignPackage`を実装する。
2. 共通情報入力欄を作成する。
3. 基本6設計書を初期選択する。
4. 条件付き6設計書をチェックボックスで選択できるようにする。
5. 全選択、基本のみ、全解除を実装する。
6. 選択済み設計書だけ入力セクションを表示する。

### 完了条件

- 共通情報を一度だけ入力できる。
- 基本6設計書が選択済みで開始する。
- 設計書選択に応じて入力欄が切り替わる。

## Step 3. 設計書入力フォーム

### 3.1 基本6設計書

次の順で実装する。

1. Hist
2. Outline_A
3. Outline_B
4. FuncSpec
5. FuncDetail
6. Relation

### 3.2 条件付き6設計書

基本6設計書の生成確認後に実装する。

1. Check
2. S-Layout
3. R-Layout
4. Event
5. Others
6. Footnote

### 共通入力部品

- `input`
- `textarea`
- `select`
- `checkbox`
- 行追加式の簡易表
- 上下移動ボタン
- 複製ボタン
- 削除ボタン

### 完了条件

- 12種類すべてのテンプレート項目を入力できる。
- 表行を追加、削除、複製、上下移動できる。
- No.を自動採番できる。
- 入力値が画面状態へ反映される。

## Step 4. Markdown生成とプレビュー

### 作業

1. 共通トークンを置換する。
2. 表行をMarkdownへ変換する。
3. 処理ブロックをMarkdownへ変換する。
4. SQLを`sql`コードブロックへ変換する。
5. README索引を生成する。
6. 未置換トークンを検出する。
7. 生成したMarkdownソースを`pre`要素へ表示する。

### 完了条件

- 基本6設計書がテンプレート構造どおり生成される。
- 条件付き設計書が選択時だけ生成される。
- README索引と生成ファイルが一致する。
- 入力されていない内容を推測しない。
- 未置換トークンがある場合は出力を停止する。

## Step 5. 画像、ZIP、自動保存

### 5.1 画像

1. S-LayoutとR-Layoutへ画像選択欄を追加する。
2. PNG、JPEG、WebPを検証する。
3. サムネイルを表示する。
4. 表示名、alt、備考、順序を編集できるようにする。
5. Markdown画像セクションを生成する。
6. 画像を`sheets/S-Layout/`または`sheets/R-Layout/`へ追加する。

### 5.2 ZIP

1. READMEをルートへ追加する。
2. Markdownを`sheets/`へ追加する。
3. 画像を同名フォルダへ追加する。
4. Markdown参照先と画像パスを照合する。
5. `<機能ID>_<機能名>.zip`をダウンロードする。

### 5.3 自動保存

1. 文字入力と表データをLocal Storageへ保存する。
2. 起動時に保存内容を復元する。
3. 入力クリアで保存内容を削除する。
4. 画像バイナリは保存しない。
5. 画像選択中の再読み込みは警告する。

### 完了条件

- 正しいフォルダ構成のZIPを出力できる。
- 画像を同名フォルダへ出力できる。
- 画像なしの場合は画像フォルダを生成しない。
- 文字入力を再読み込み後に復元できる。

## 6. 実装上の単純化ルール

- 設計書定義はTypeScriptの静的配列で管理する。
- フォームを汎用スキーマエンジンから自動生成しない。
- テンプレート条件分岐を実装しない。
- 画像処理は`imageAssets.ts`へまとめる。
- ZIP処理は`zipExporter.ts`へまとめる。
- 保存処理は`storage.ts`へまとめる。
- HTMLレンダリングプレビューは実装しない。
- 画像バイナリの永続化は実装しない。
