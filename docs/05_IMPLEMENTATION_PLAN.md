# Docs Generator 実装計画

## 1. 実装方針

- 一機能分のMarkdown設計書を作成・再編集・出力できる最小構成を先に完成させる。
- 基本6設計書を優先し、その後に条件付き6設計書を追加する。
- テンプレート、フォームスキーマ、検証、生成処理を設計書単位でまとめて実装する。
- 各作業単位は、画面だけ、生成だけで分断せず、入力から出力まで動作する縦断単位とする。
- 実装の正しさは、提供テンプレートに近いMarkdownが生成されることをゴールデンテストで保証する。

## 2. 完成条件

初期リリースは、次を満たした時点で完成とする。

- 新規機能設計を作成できる。
- 基本6設計書が初期選択される。
- 条件付き設計書を追加・解除できる。
- 共通メタデータを一度の入力で全設計書へ反映できる。
- 12種類すべての設計書をフォームから編集できる。
- 提供テンプレートとほぼ同じ見出し・表構造で出力できる。
- README索引と生成ファイルが一致する。
- ZIP出力できる。
- 入力途中を自動保存して再開できる。
- 本ツールが生成したMarkdownを再読込できる。
- 主要な単体、生成、E2Eテストが通る。

## 3. 実装順序

## M01 プロジェクト基盤

### 作業

- Vue 3 + TypeScript + Viteの初期構成を作成する。
- Pinia、Vue Router、Zod、Vitest、Playwrightを導入する。
- ESLint、Prettier、型チェック、テストコマンドを設定する。
- `src`ディレクトリをシステム設計書の構成に合わせる。
- CIでlint、typecheck、unit test、buildを実行する。

### 成果物

- 起動可能なWebアプリケーション
- 共通レイアウト
- ルーティング
- CI設定

### 完了条件

- `npm run dev`で起動できる。
- `npm run build`が成功する。
- CIで基本チェックが成功する。

## M02 テンプレート基盤

### 作業

- `docs/templates`のMarkdownテンプレートをアプリから参照可能にする。
- `template-manifest.json`を読み込む。
- Handlebarsの初期化と共通ヘルパーを実装する。
- テンプレートバージョンを扱う。
- READMEと各設計書の出力順を一元管理する。

### 成果物

- TemplateService
- Template Registry
- Handlebarsヘルパー
- マニフェスト検証スキーマ

### 完了条件

- テストデータからREADMEと空の設計書テンプレートを展開できる。
- テンプレートパス、出力パス、順序をマニフェストだけで取得できる。
- 不正なマニフェストを起動時に検出できる。

## M03 共通ドメインと保存

### 作業

- `FeatureDocumentProject`、`CommonMetadata`、`DocumentType`を実装する。
- 新規プロジェクト初期化処理を実装する。
- IndexedDBとDexieを導入する。
- 自動保存と復元を実装する。
- 最近編集した設計一覧を実装する。
- プロジェクトプリセットを実装する。

### 完了条件

- ブラウザ更新後も入力内容を復元できる。
- 新規、開く、複製、削除ができる。
- 共通メタデータを一箇所で管理できる。

## M04 ホームと新規作成

### 作業

- DG01ホームを実装する。
- 新規作成ダイアログを実装する。
- プリセット、機能種別、機能ID、機能名の4項目で開始できるようにする。
- 作成日、Rev、作成者、初回履歴の初期値を設定する。

### 完了条件

- 3操作以内で編集画面へ移動できる。
- 新規プロジェクトに基本6設計書が選択される。
- 機能種別に応じた追加設計書が推奨される。

## M05 基本情報と設計書選択

### 作業

- DG02基本情報フォームを実装する。
- 設計書選択UIを実装する。
- 基本設計書解除時の警告を実装する。
- 機能種別別の推奨ルールを実装する。
- 選択変更時に対象設計書モデルを初期化する。

### 完了条件

- 共通項目の変更が全テンプレートコンテキストへ反映される。
- 未選択設計書が生成対象から外れる。
- 選択を解除しても、再選択に備えて入力データを保持できる。

## M06 共通フォーム部品

### 作業

- テキスト、複数行、日付、選択、チェックボックスを実装する。
- 繰り返し表を実装する。
- 行追加、削除、複製、並び替え、Undoを実装する。
- 番号付きステップ入力を実装する。
- SQLエディタを実装する。
- 設計書参照セレクタを実装する。
- フィールド単位の検証表示を実装する。

### 完了条件

- 各設計書固有フォームを共通部品の組合せで作成できる。
- キーボードで表行を追加し入力を継続できる。
- 表の順番が出力へ反映される。

## M07 Hist / Outline_A / Outline_B

### 作業

- 各フォームスキーマを実装する。
- 初期データ作成、検証、テンプレートコンテキスト変換を実装する。
- 各Markdownテンプレートを適用する。
- ゴールデンファイルテストを追加する。

### 完了条件

- 初回履歴が自動生成される。
- フローが番号付きリストで出力される。
- CRUDと関連資源が表として出力される。
- 出力がテンプレート構造と一致する。

## M08 FuncSpec / FuncDetail / Relation

### 作業

- 複数機能単位、複数処理単位、複数リレーションに対応する。
- 処理ステップの自動採番を実装する。
- 入力がある`try / catch / finally`だけを出力する。
- Transfer SourceとTransfer Destinationを別セクションで出力する。
- SQLコードブロックを生成する。
- 選択済み設計書だけを相互参照へ表示する。

### 完了条件

- 基本6設計書を一機能分まとめて生成できる。
- SQLが入力どおりに出力される。
- 存在しない設計書へのリンクが生成されない。

## M09 条件付き6設計書

### 作業

- S-Layout
- R-Layout
- Event
- Check
- Others
- Footnote

各設計書について、フォームスキーマ、検証、テンプレートコンテキスト、生成テストを実装する。

### 完了条件

- 12種類すべてを選択・編集・生成できる。
- CheckとEventの空表枠を互換モードで保持できる。
- S-LayoutのコントロールID参照が整合する。

## M10 プレビューと検証

### 作業

- DG04を実装する。
- Markdownソースとレンダリング表示を実装する。
- ファイル切替を実装する。
- エラー、警告、情報の一覧を実装する。
- 問題箇所から入力欄へ移動できるようにする。
- 内容による追加設計書提案を実装する。

### 完了条件

- 入力変更後500ms以内を目標にプレビューが更新される。
- 出力を止めるエラーと確認可能な警告を区別できる。
- README索引不一致を検出できる。

## M11 Markdownパッケージ出力

### 作業

- README生成を実装する。
- UTF-8/LF整形を実装する。
- JSZipによるZIP出力を実装する。
- File System Access APIによる直接保存を実装する。
- 非対応ブラウザではZIPへフォールバックする。
- ファイル名正規化と上書き確認を実装する。

### 完了条件

- README以外がすべて`sheets`へ出力される。
- 索引とファイルが一致する。
- ZIP展開後の相対リンクが有効である。
- 12ファイルを含むパッケージを出力できる。

## M12 Markdown再読込

### 作業

- README解析を実装する。
- 規定見出しと表のパーサーを実装する。
- 各設計書の`fromParsedMarkdown`を実装する。
- 未知ブロックの保持を実装する。
- テンプレートバージョン差異の警告を実装する。
- ZIP、フォルダ、ドラッグ&ドロップに対応する。

### 完了条件

- 本ツールで生成したパッケージを再読込し、同等内容を再出力できる。
- 未知セクションが消失しない。
- 大幅に変更されたMarkdownを無警告で上書きしない。

## M13 操作削減と仕上げ

### 作業

- 前回値の再利用を実装する。
- プリセット管理を仕上げる。
- 複製作成を実装する。
- キーボード操作を改善する。
- 未入力セクションの折りたたみを実装する。
- アクセシビリティを確認する。
- エラー表示と空状態を整える。

### 完了条件

- 新規作成開始時の手入力が4項目以内である。
- 共通情報の再入力が不要である。
- マウスだけ、キーボードだけの両方で主要操作ができる。

## M14 リリース準備

### 作業

- READMEへセットアップ、操作、出力例を記載する。
- サンプルプロジェクトを用意する。
- 主要ブラウザで動作確認する。
- ライセンスと依存ライブラリを確認する。
- GitHub Pagesまたは静的ホスティング手順を整備する。

### 完了条件

- 新規利用者がREADMEだけで起動できる。
- サンプルから出力結果を確認できる。
- 全受入条件とリリーステストを通過する。

## 5. 最優先の実装範囲

最初の実用版は、次に絞って完成させる。

1. 新規作成
2. 共通メタデータ
3. 基本6設計書
4. テンプレート駆動生成
5. Markdownプレビュー
6. 入力検証
7. ZIP出力
8. 自動保存

条件付き6設計書とMarkdown再読込は、基本6設計書の出力品質を確定した後に追加する。

## 6. 実装時の禁止事項

- テンプレートと生成コードの両方に見出しを重複定義しない。
- 12種類すべてを一つの巨大フォームコンポーネントへ実装しない。
- UIモデルをそのまま永続化・出力モデルとして使わない。
- Markdown本文を正規表現だけで全面解析しない。
- 入力内容を無断で要約・補完しない。
- 再読込時に未知の記述を破棄しない。
