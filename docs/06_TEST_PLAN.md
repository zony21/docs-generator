# Docs Generator テスト計画

## 1. 目的

Docs Generatorが、入力された内容を変更せず、テンプレートに近いMarkdown設計書として正しい階層で出力できることを確認する。

初期実装では、生成処理、テンプレート、画像パス、ZIP構成を重点的に検証する。

## 2. テスト種別

| 種別 | 対象 |
| --- | --- |
| 単体テスト | 置換、表、SQL、ファイル名、画像パス、保存 |
| テンプレートテスト | 必須テンプレートとトークン |
| ZIPテスト | README、sheets、画像フォルダ |
| 手動確認 | 1画面の入力からZIP出力まで |

初期実装ではPlaywright、コンポーネントテスト、Markdown再読込テストを導入しない。

## 3. テンプレート検証

- `templates/README_TEMPLATE.md`が存在する。
- 12種類の設計書テンプレートが存在する。
- 設計書定義のテンプレートパスが重複しない。
- 出力パスが重複しない。
- 基本6設計書が初期選択として定義される。
- READMEに`{{SHEET_INDEX_ROWS}}`が存在する。
- S-LayoutとR-Layoutに`{{LAYOUT_IMAGE_SECTION}}`が存在する。
- 生成結果へ`{{TOKEN}}`が残らない。

## 4. 共通メタデータ

- システム名が全生成ファイルへ反映される。
- モジュール名とモジュールIDが全生成ファイルへ反映される。
- 機能IDと機能名が全生成ファイルへ反映される。
- Date、Rev、Doc Number、Authorが全生成ファイルへ反映される。
- 任意項目が空でも未置換トークンが残らない。
- 同じ共通項目を設計書ごとに入力する必要がない。

## 5. 設計書選択

- 新規状態で基本6設計書が選択される。
- 条件付き6設計書は未選択で開始する。
- 全選択が動作する。
- 基本のみが動作する。
- 全解除が動作する。
- 未選択設計書がREADME索引とZIPから除外される。
- 選択済み設計書だけ入力欄が表示される。

## 6. Markdown生成共通

### 6.1 文字列

- 日本語、英数字、記号を出力できる。
- 入力内容を自動で要約、補完、言い換えしない。
- 改行を用途に応じて維持できる。

### 6.2 表

- 入力行順を維持する。
- セル内の`|`を`\|`へ変換する。
- セル内改行を`<br>`へ変換する。
- 空の表でもテンプレートの見出しが残る。
- No.列を自動採番できる。

### 6.3 手順

- 1行1ステップを番号付きリストへ変換する。
- 空行を除外する。
- 並び替え後の順番を反映する。

### 6.4 SQL

- 改行とインデントを保持する。
- SQL内容を変更しない。
- 入力がある場合だけ`sql`コードブロックを生成する。

## 7. 設計書別テスト

### 7.1 Hist

- 初回履歴を共通情報から作成できる。
- 履歴行順を維持する。
- 承認項目が空でも表が崩れない。

### 7.2 Outline_A

- 目的、範囲、フロー、前提、後続条件を出力できる。
- フローを番号付きリストにできる。

### 7.3 Outline_B

- 処理分類、CRUD、関連資源、制約を出力できる。
- 表の列順と行順を維持する。

### 7.4 FuncSpec

- 複数アクションを出力できる。
- Intent、Major steps、Success path、Error pathを区別できる。
- 未入力のError pathを補完しない。

### 7.5 FuncDetail

- 複数処理単位を出力できる。
- 入力のあるtry、catch、finallyだけを出力する。
- 選択済み設計書だけをCross referencesへ出力する。

### 7.6 Relation

- Transfer SourceとTransfer Destinationを分離する。
- SQLを`sql`コードブロックへ出力する。

### 7.7 S-Layout

- 画面領域、コントロール、属性、表示編集ルールを出力できる。
- 画像を`sheets/S-Layout/`へ出力できる。

### 7.8 R-Layout

- レイアウト領域、出力項目、列定義、出力規則を出力できる。
- 画像を`sheets/R-Layout/`へ出力できる。

### 7.9 Event

- 標準4列のイベント表を出力できる。

### 7.10 Check

- Validation contextと標準6列表を出力できる。
- No.を自動採番できる。

### 7.11 Others

- 定数、選択肢、補助マッピングを出力できる。

### 7.12 Footnote

- 用語、略称、注釈を出力できる。
- 入力していない説明を追加しない。

## 8. README生成

- H1へ機能IDと機能名を出力する。
- 共通メタデータを出力する。
- 選択済み設計書だけ索引へ掲載する。
- 設計書定義順に索引を並べる。
- 索引リンクがZIP内のMarkdownを指す。
- 索引行数と生成Markdown数が一致する。

## 9. 画像テスト

### 9.1 形式と制限

- PNGを追加できる。
- JPEGを追加できる。
- WebPを追加できる。
- SVG、GIF、PDFを拒否する。
- 10MB超過を拒否する。
- 1設計書11枚目を拒否する。

### 9.2 ファイル名

- 禁止文字を`_`へ変換する。
- 拡張子を小文字化する。
- 同名時に`-2`、`-3`を付ける。
- `../`を除去する。

### 9.3 階層と参照

- S-Layout画像を`sheets/S-Layout/`へ出力する。
- R-Layout画像を`sheets/R-Layout/`へ出力する。
- 画像が0件の場合は画像フォルダを作成しない。
- Markdownへ相対パスを出力する。
- Markdown参照先がZIP内に存在する。
- 削除済み画像がZIPへ残らない。

## 10. Local Storage

- 文字入力を保存できる。
- 表データを保存できる。
- 選択済み設計書を保存できる。
- 再読み込み後に復元できる。
- 入力クリアで保存データを削除できる。
- Fileオブジェクトを保存しない。

## 11. ZIP構成

- ルートに`README.md`だけが存在する。
- その他のMarkdownが`sheets/`配下に存在する。
- 選択した設計書だけが含まれる。
- 画像が同名フォルダに存在する。
- 文字コードがUTF-8である。
- README索引とファイルが一致する。

## 12. 手動確認シナリオ

1. ツールを開く。
2. 共通情報を入力する。
3. 基本6設計書へ内容を入力する。
4. S-Layoutを追加する。
5. PNG画像を1枚添付する。
6. Markdownソースを確認する。
7. ZIPを出力する。
8. ZIPを展開する。
9. READMEからS-Layoutを開く。
10. S-Layoutから画像を表示できることを確認する。

## 13. 完了基準

- `npm test`が成功する。
- `npm run build`が成功する。
- 手動確認シナリオが成功する。
- 参照切れがない。
- 未置換トークンがない。
- 入力していない設計内容が生成されない。
