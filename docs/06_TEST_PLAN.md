# Docs Generator テスト計画

## 1. 目的

Docs Generatorが、入力された設計情報と画像を失わず、提供テンプレートに近い構造のMarkdown設計書として正しく生成・保存・再読込できることを確認する。

特に次を重点的に検証する。

- テンプレートと生成結果の見出し・表構造
- README索引と実ファイルの一致
- 未入力情報を推測しないこと
- 画像の階層、参照、保存、再読込
- Markdown再読込時の情報保持

## 2. テスト種別

| 種別 | 対象 |
| --- | --- |
| 単体テスト | ドメインルール、検証、整形、ファイル名、推奨判定 |
| テンプレートテスト | Handlebars展開、見出し、表、空欄、リンク、画像 |
| ゴールデンテスト | 代表入力に対する完成Markdown全文比較 |
| コンポーネントテスト | 入力部品、表操作、画像操作、検証表示 |
| 結合テスト | フォームからプレビュー、保存、出力まで |
| E2Eテスト | 一機能分の新規作成、ZIP出力、再読込 |
| 非機能テスト | 性能、ブラウザ、アクセシビリティ、セキュリティ |

## 3. テンプレート・マニフェスト検証

- ルートREADMEテンプレートが存在する。
- マニフェスト記載の全テンプレートが存在する。
- DocumentType、出力パス、出力順が重複しない。
- 基本6設計書が`requiredByDefault=true`である。
- 条件付き6設計書が機能種別に応じて推奨される。
- テンプレート内の必須変数がフォームスキーマから供給される。
- 未登録Handlebarsヘルパーを使用していない。
- テンプレートバージョンが有効である。
- 生成結果に未展開の`{{placeholder}}`が残らない。

## 4. 共通メタデータ

- システム名、モジュール名、モジュールIDが全生成ファイルへ反映される。
- 機能ID、機能名が全生成ファイルへ反映される。
- Date、Rev、Doc Number、Authorが全生成ファイルへ反映される。
- 共通情報変更後、全プレビューが更新される。
- 同じ共通項目を設計書ごとに再入力しなくてよい。
- 任意項目が空の場合、テンプレート規則どおりに出力される。

## 5. 新規作成・設計書選択

- プリセット、機能種別、機能ID、機能名の4項目で開始できる。
- 作成日、Rev、作成者、Hist初回行が自動設定される。
- 基本6設計書が初期選択される。
- 機能種別に応じて追加設計書が推奨される。
- 設計書を追加・解除できる。
- 基本設計書解除時に警告される。
- 解除した設計書がREADME索引と出力対象から消える。
- 再選択時に以前の入力値を復元できる。

## 6. 共通フォーム部品

### 6.1 テキスト

- 日本語、英数字、記号を入力できる。
- Markdown特殊文字を安全に出力できる。
- 入力文言を勝手に要約・補完しない。

### 6.2 繰り返し表

- 行追加、削除、複製、並び替え、Undoができる。
- 空行を検出できる。
- 入力順がMarkdown表へ反映される。
- セル内の`|`がエスケープされる。

### 6.3 処理ステップ

- 自動採番される。
- 並び替え後に再採番される。
- 空ステップが警告される。

### 6.4 SQL

- 改行とインデントを保持する。
- SQL内容を自動変更しない。
- 空SQLでは不要なコードブロックを出力しない。

## 7. 設計書別テスト

### 7.1 Hist

- 初回履歴が生成される。
- 履歴行の順序が維持される。
- 承認項目が空でも表構造が崩れない。

### 7.2 Outline_A

- Purpose、Scope、対象者、フロー、前提・後続条件を出力できる。
- フローを番号付きリストで出力できる。
- 未入力フローを推測しない。

### 7.3 Outline_B

- 処理分類、CRUD、関連資源、制約を出力できる。
- 表の行順を保持できる。

### 7.4 S-Layout

- 画面領域、コントロール一覧、属性、表示編集ルールを出力できる。
- コントロールID重複を検出できる。
- 画像を`S-Layout/`へ出力できる。

### 7.5 R-Layout

- レイアウト領域、出力項目、列定義、出力規則を出力できる。
- 画像を`R-Layout/`へ出力できる。

### 7.6 FuncSpec

- 複数機能単位を出力できる。
- Trigger、Intent、Major steps、Success path、Error pathを区別できる。
- 未入力のError pathを補完しない。

### 7.7 Event

- 標準4列のイベント表を出力できる。
- 互換モードで空表枠を保持できる。

### 7.8 FuncDetail

- 複数処理単位を出力できる。
- 入力のあるtry/catch/finallyだけを出力する。
- 選択済み設計書だけをCross referencesへ出力する。

### 7.9 Relation

- Transfer SourceとTransfer Destinationを分離する。
- SQLを`sql`コードブロックで出力する。
- SQLを再整形しない。

### 7.10 Check

- Validation contextと標準6列表を出力できる。
- No.を自動採番できる。
- 互換モードで空表枠を保持できる。

### 7.11 Others

- 定数、コード値、キー割当、補助マッピングを出力できる。

### 7.12 Footnote

- 用語、略称、注釈を出力できる。
- 入力されていない用語説明を追加しない。

## 8. README生成

- H1に機能IDと機能名を出力する。
- Featureに共通メタデータを出力する。
- 選択済み設計書だけを索引へ掲載する。
- マニフェスト順に索引を並べる。
- 各リンクが実ファイルを指す。
- 実ファイル数と索引行数が一致する。
- README以外のMarkdownが`sheets`配下にある。

## 9. 空欄処理

- 未選択設計書は生成されない。
- 主要内容がすべて空の選択済み設計書は警告される。
- 警告を許可した場合は`No concrete entries.`が出力される。
- CheckとEventは設定に応じて空表枠を保持する。
- 任意セクションが空の場合、不要なテンプレート記号が残らない。

## 10. 画像テスト

### 10.1 追加・編集

- PNG、JPEG、WebP、SVGを追加できる。
- 非対応形式を拒否できる。
- ファイル選択、ドラッグ&ドロップ、貼り付けに対応する。
- 複数画像の追加順を保持する。
- 代替テキストを必須検証できる。
- キャプション、関連先、出力名を編集できる。
- 並び替え、置換、削除、Undoができる。

### 10.2 ファイル名

- 禁止文字を正規化する。
- 拡張子を小文字化する。
- 重複時に`-2`、`-3`を付与する。
- 大文字小文字だけ異なる重複を検出する。
- `..`や絶対パスを除去する。

### 10.3 出力階層

- `S-Layout.md`の画像が`sheets/S-Layout/`へ出力される。
- `R-Layout.md`の画像が`sheets/R-Layout/`へ出力される。
- 任意設計書画像が対象Markdown名と同じフォルダへ出力される。
- 画像0件では画像フォルダを生成しない。
- `sheets/images`共通フォルダを生成しない。

### 10.4 Markdown参照

- `![alt](S-Layout/file.png)`形式で出力される。
- 相対パスに`\`を使用しない。
- ZIP展開後も画像が表示される。
- 参照切れをErrorとして検出する。
- 未参照画像をWarningとして検出する。

### 10.5 保存・再読込

- 画像Blobを自動保存できる。
- ブラウザ更新後に画像を復元できる。
- 画像付きZIPを再読込できる。
- 代替テキスト、キャプション、表示順を復元できる。
- 画像置換後も関連先を保持できる。

### 10.6 セキュリティ

- MIME typeと拡張子不一致を検出する。
- 危険なSVGを拒否またはサニタイズする。
- Zip Slipを防止する。
- サイズ、ファイル数、展開容量制限を適用する。
- 外部画像URLを既定で読み込まない。

## 11. 自動保存

- 入力変更後にデバウンスして保存される。
- ブラウザ更新後に復元できる。
- 保存失敗時に入力が失われない。
- 複数タブ競合を警告できる。
- プロジェクト削除時に画像Blobも削除される。

## 12. ZIP・フォルダ出力

- 正しいフォルダ名で出力される。
- UTF-8、LF、末尾改行でMarkdownを保存する。
- 画像はバイナリのまま保存する。
- ZIP展開後にMarkdownと画像を開ける。
- File System Access API非対応時にZIPへフォールバックする。
- 上書き前に確認される。

## 13. Markdown再読込

### 13.1 ラウンドトリップ

1. 入力モデルからMarkdownと画像を生成する。
2. パッケージを再読込する。
3. 再度出力する。
4. 意味のある内容、画像、順序、リンクが一致することを確認する。

### 13.2 検証項目

- READMEから設計書一覧を取得できる。
- 共通メタデータ、表行、処理ステップ、SQLを復元できる。
- 画像パス、代替テキスト、キャプションを復元できる。
- 未知セクションを保持できる。
- テンプレートバージョン差異を警告できる。
- 大幅に変更されたMarkdownを無警告で上書きしない。

## 14. ゴールデンファイル

各設計書に次のケースを用意する。

1. 最小入力
2. 標準入力
3. 複数行・特殊文字・複数データ
4. 空欄警告を含むケース
5. 画像付きケース（S-Layout、R-Layout）

テンプレート変更により期待結果が変わる場合、差分をレビューしてからゴールデンファイルを更新する。

## 15. 性能目標

- 通常入力反映：100ms以内を目標
- Markdownプレビュー更新：500ms以内を目標
- 12設計書生成：3秒以内を目標
- 画像10件を含むプレビュー更新で操作不能にならないこと
- 100MB以内のパッケージ出力でブラウザが異常終了しないこと

## 16. 対応ブラウザ

- Chrome最新版
- Edge最新版
- Firefox最新版
- Safari最新版

File System Access API非対応ブラウザではZIP出力が機能することを確認する。

## 17. リリース判定

- 全単体テストが成功する。
- 全テンプレートのゴールデンテストが成功する。
- 新規作成からZIP出力までのE2Eが成功する。
- 画像付きパッケージのE2Eが成功する。
- 再読込ラウンドトリップテストが成功する。
- Critical/Highの既知不具合がない。
- README索引、Markdown、画像参照に不整合がない。
